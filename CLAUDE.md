# Reglas de Comportamiento del Agente

## Principio de Veracidad y Auditoría
- **PROHIBIDO ADIVINAR:** No asumas, imagines ni deduzcas el contenido de ningún archivo del repositorio sin haberlo leído previamente de forma explícita.
- **USO OBLIGATORIO DE TOOLS:** Antes de responder cualquier pregunta sobre la estructura, lógica o contenido del proyecto, debes ejecutar la herramienta correspondiente (`view_file`, `grep`, `ls`) para verificar el estado real del código.
- **CERO DISCULPAS, MÁS ACCIÓN:** No pierdas tiempo ni tokens pidiendo disculpas por errores previos. Si cometes un error, corrígelo ejecutando la herramienta adecuada de inmediato.
- **MENTALIDAD DE CODE REVIEW:** Trata el análisis del código con el rigor de un Senior Software Engineer. Si no has leído un archivo, declara explícitamente: "No poseo los datos actualizados de este archivo porque no lo he leído" \n\n## Sistema de Persistencia (LocalCode)\n- **Continuidad de Sesión:** El proyecto utiliza la carpeta `.localcode` como la fuente primaria de verdad para el estado del proyecto. Al iniciar cada sesión, es obligatorio consultar `.localcode/SESSION.md` para sincronizar el contexto actual y los pasos a seguir.\n- **Consulta de Estado:** Al iniciar una tarea o si hay dudas sobre el progreso actual, consulta siempre `.localcode/SESSION.md`. Este archivo contiene el resumen del estado actual y los próximos pasos.\n- **Referencia de Contexto:** Utiliza `.localcode/CONTEXT_MAP.md` para entender las relaciones entre archivos y `.localcode/ROADMAP.md` para la visión general del proyecto.\n- **Registro de Decisiones:** Consulta `.localcode/DECISIONS.md` antes de proponer cambios arquitectónicos importantes para evitar revertir decisiones previas.\n
